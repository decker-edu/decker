This guide tells an LLM how to **author Decker content and prove it is correct**
before reporting done. Part 1 is the validation feedback loop (the part syntax
docs omit). Part 2 is the complete syntax reference.

**Relationship to `CLAUDE.md`:** this guide (with its companion
`.claude/skills/decker/SKILL.md`) is the authoritative source for **generic**
Decker syntax and validation. A project's `CLAUDE.md` should hold only
**project-specific** context — this repo's conventions, directory layout, naming
rules, publishing target — and should not restate generic Decker how-to, which
this guide supersedes.

# Part 1 — The validation loop

Decker is a Shake build system: each source file compiles to an HTML file under
`public/`. After writing or editing any `*-deck.md`, `*-page.md`, or
`*-quest.yaml`, run all three steps. **Never report "done" after step 1 alone.**

## 1. Map source → build target

The target mirrors the source path under `public/`:

| Source                        | Build target                       |
|-------------------------------|------------------------------------|
| `unit/07-deck.md`             | `public/unit/07-deck.html`         |
| `assignments/a01-page.md`     | `public/assignments/a01-page.html` |
| `index.md`                    | `public/index.html`                |
| `topic/x/quests/*-quest.yaml` | aggregated — see "Questions & exams"|

## 2. Build just that target and read the exit code

Build the single target (faster, and scopes errors to your file):

```
decker public/unit/07-deck.html
```

**Exit code is authoritative for hard errors:**

- **Exit 1** = hard build error. Decker prints `Error when running Shake build
  system` and usually `file does not exist and no rule available: <path>`. The
  HTML is **not** produced (or left stale). Causes: missing `[:include](...)`
  target, missing `![](image.png)`, missing static resource. Fix before moving on.
- **Exit 0** = build succeeded — but this does **not** guarantee the content is
  correct. See step 3.

**Warning discipline (important):** the dev build prints a banner line beginning
`WARNING: You are running a development build`. That is **not** a content
problem — ignore it. Real content warnings from pandoc are **bracketed**
(`[WARNING] ...`). Match the bracket form:

```
decker public/unit/07-deck.html 2>&1 | grep -E '\[WARNING\]|Error when running Shake'
```

## 3. Inspect the HTML for *silent* problems (exit 0 can still be wrong)

Some breakage does not fail the build — decker emits HTML with the mistake baked
in. Catch these by looking at the output:

- **Unresolved citation** → `[WARNING] Citeproc: citation <Key> not found`, and
  the raw key (e.g. `NoSuchKey2099`) is written **literally** into the HTML.
  After a fix, `grep -o '<CiteKey>' public/.../file.html` should find nothing.
- **Unresolved Wikipedia links** (`[§wen](Article "Text")`) — verify it rendered
  as an anchor, not literal `§wen` text.
- **Stale output** — confirm the target's mtime updated. If decker decided
  "nothing changed," force it: `decker -B public/.../file.html`.
- **Empty/misparsed slides or questions** — a YAML or fence mistake can silently
  drop content. Confirm the expected text is present in the HTML.

Open the HTML to eyeball layout when structure matters (columns, fragments,
popups); otherwise grep for the specific strings you added.

## Questions & exams (`*-quest.yaml`)

Quest files are **not** built to per-file HTML; they aggregate into the exam
browser:

- Build with `decker exam-builder` (target `public/exam-builder/questions.json`).
- **New quest files require a forced rebuild** — a running server or incremental
  build won't pick them up: `decker -B exam-builder`.
- Validate by confirming the question appears in
  `public/exam-builder/questions.json` (grep its `Title`/`TopicId`).
- **Equivalence:** files sharing `LectureId` + `TopicId` are randomized variants
  — only one is drawn per student exam. Keep variants equal in difficulty and
  choice count.

## Command quick reference

| Purpose                          | Command                         |
|----------------------------------|---------------------------------|
| Build one deck/page              | `decker public/<path>.html`     |
| Force-rebuild one target         | `decker -B public/<path>.html`  |
| Rebuild exam questions           | `decker -B exam-builder`        |
| Check external tools present     | `decker check`                  |
| Show project targets/params      | `decker info`                   |
| Print version (stamp this guide) | `decker version`                |
| Start preview server             | `decker serve`                  |
| Format Markdown (stdin→stdout)   | `decker format`                 |

**Loop in one line:**
`decker public/<t>.html 2>&1 | grep -E '\[WARNING\]|Error when running Shake'`
→ exit 1: fix the missing dependency; warnings: fix them; then grep the generated
HTML for the content you added.

# Part 2 — Complete syntax reference

## File types

| Pattern        | Description          | Output            |
|----------------|----------------------|-------------------|
| `*-deck.md`    | Presentation slides  | HTML slide deck   |
| `*-page.md`    | Static content pages | HTML page         |
| `*-quest.yaml` | Quiz/exam questions  | Interactive polls |

## Slide decks (`*-deck.md`)

Markdown compiled into reveal.js presentations.

### Basic structure

````markdown
---
lang: en-UK
title: Slide Deck Title
---

# First Slide Title

## Subtitle or Section

- Bullet point content
- More content

--------------------------------------------------------------------------------

# Second Slide Title

Content for the second slide.
````

### YAML frontmatter

```yaml
---
lang: en-UK                 # Language code (en-UK, en-EN, de-DE)
title: "Presentation Title" # Document title
lecture:
  status: upcoming          # Lecture status (done, draft, upcoming)
---
```

### Slide separators

- A line of **exactly 80 dashes** separates slides. Off-count runs are treated as
  body content and silently merge slides.
- Each `# Heading` also starts a new slide section.

### Slide classes and attributes

Apply classes with `{.class}` syntax:

````markdown
# Slide with Classes {.columns}

## Left Column {.left grow="2"}

Content on the left.

## Right Column {.right grow="3"}

Content on the right.

## Bottom Section {.bottom .fragment}

Appears at the bottom after a click.
````

Common slide classes:

| Class                   | Description                      |
|-------------------------|----------------------------------|
| `.columns`              | Enable column layout on slide    |
| `.left`, `.right`       | Position content in columns      |
| `.top`, `.bottom`       | Vertical positioning             |
| `.fragment`             | Reveal on click/keypress         |
| `.incremental`          | Make list items fragments        |
| `.accent0` - `.accent4` | Color accent classes             |
| `.solution`             | Mark as solution (can be hidden) |
| `.sub`                  | Sub-slide (continuation)         |

Column layout uses `grow` to allocate proportional space:

```markdown
## Column {.left grow="2"}    # Takes 2 parts of available space
## Column {.right grow="3"}   # Takes 3 parts of available space
```

Popup slides overlay content:

```markdown
## Important Note {.fragment .accent1 popup="center-up"}

This content appears as a centered popup overlay.
```

Popup positions: `center`, `center-up`, `center-down`.

### Code blocks

Static code — fence with a language identifier:

````markdown
```haskell
factorial n = product [1..n]
```
````

Live/interactive code (Decker-specific). **`.live-code-` has a trailing dash on
purpose** — it is the executable-editor marker. Never "fix" it to `.live-code`:

````markdown
```{#id .live-code- language="Haskell" sandbox="GHCi"}
factorial 5
```
````

Live code with dependencies (`depends-on` references another block's id):

````markdown
```{#base .live-code- language="Haskell"}
x = 42
```

```{.live-code- language="Haskell" depends-on="base"}
main = print x
```
````

Hidden live code (available to dependents but not displayed) via `.display-none`:

````markdown
```{#hidden .live-code- .display-none language="Haskell"}
-- available but not shown
helper x = x + 1
```
````

### Including other decks

`[:include](path)` inlines another file. A wrong path is a **hard** build failure
(exit 1), so mistakes here can't slip through silently:

```markdown
[:include](../topic/motivation/motivation.md)
```

### Special links

Wikipedia links — the `§wen`/`§wde` prefix is required:

```markdown
[§wen](Article_Name "Display Text")   # English Wikipedia
[§wde](Artikel_Name "Anzeigetext")    # German Wikipedia
```

Live-code server declaration:

```markdown
[§live-code-server](https://example.com/codapi/v1)
```

### Citations

Pandoc citation syntax with BibTeX keys (bibliography configured in
`decker.yaml`, here `bibliography/plc-bibliography.bib`). An unknown key produces
a `[WARNING]` and renders literally into the HTML — always verify:

```markdown
According to [@Author:2020], this concept...

Multiple citations [@Smith:2019; @Jones:2021]
```

### Math (LaTeX)

```markdown
Inline math: $$E = mc^2$$

Display math:
$$$$
\bar{x} = \frac{1}{n}\sum_{i=1}^n x_i
$$$$
```

### Images

```markdown
![Alt text](image.png){width="50%"}

![Caption](image.svg){.raw style="height:1em;vertical-align:baseline;"}
```

A missing image path is a **hard** build failure (exit 1).

## Static pages (`*-page.md`)

Simpler Markdown documents (assignments, docs, supplementary material).

````markdown
---
generate-ids: false   # Disable automatic ID generation
lang: en-UK
title: "Page Title"
---

# Main Heading

Regular markdown content here.

## Section

More content with lists, code, images, etc.
````

Pages support all standard Markdown: headings, paragraphs, lists, fenced code,
images/links, tables, citations, and LaTeX math.

## Quiz questions (`*-quest.yaml`)

Multiple-choice questions for exams and interactive lectures, typically in
`topic/<lecture>/quests/`.

### Equivalence and randomization

Questions sharing the same `LectureId` **and** `TopicId` are equivalent variants.
During exam construction only **one** variant per group is selected per student —
enabling personalized exams and discouraging memorization. Keep variants at the
same difficulty, with the same number of choices, testing the same concept.

### Structure

```yaml
Points: 1                   # Integer: point value (typically 1)
LectureId: functional       # String: lecture identifier
TopicId: recursion          # String: topic identifier within the lecture
Answer:
  tag: MultipleChoice       # always "MultipleChoice"
  Choices:
    - Correct: true         # Boolean: is this a correct answer?
      TheAnswer: "Answer text"
    - Correct: false
      TheAnswer: "Wrong option"
Title: Question Title       # short title
Difficulty: Easy            # Easy | Medium | Hard
Comment: ""                 # optional, often empty
Question: |                 # multiline markdown question text
  The question text goes here.
```

Required fields: `Points`, `LectureId`, `TopicId`, `Answer` (with `tag` +
`Choices`), `Title`, `Difficulty`, `Comment`, `Question`.
Optional: `Exam` (Boolean; set `false` for surveys/polls, default `true`).

### Formatting inside questions and answers

Quest YAML is **whitespace-sensitive**: fenced code must stay indented under the
`Question: |` block scalar or the body misparses (often silently).

Code block inside a question:

````yaml
Question: |
  Consider this Haskell function:

  ```haskell
  f n = n : f (2*n)
  ```

  What does `take 4 $$ f 1` return?
````

Inline code and math in answers:

```yaml
TheAnswer: "`[1,2,4,8]`"
TheAnswer: $$|Shape|=|Float|^3+|Float|^4$$
```

Multiline answers use a block scalar:

```yaml
TheAnswer: |
  The code will fail to compile because the ownership
  of `data` was moved into the vector.
```

Multiple correct answers (surveys or multi-valid questions):

```yaml
Choices:
  - Correct: true
    TheAnswer: Python
  - Correct: true
    TheAnswer: JavaScript
  - Correct: false
    TheAnswer: Fortran
```

Naming convention: `<topic-id>-quest.yaml` (e.g. `recursion-quest.yaml`,
`ownership-move-quest.yaml`).

## Project configuration (`decker.yaml`)

Root config controlling Decker behavior (abridged; this project's actual file is
authoritative):

```yaml
author: "Author Name"
subtitle: "Course Title"
resource-pack: exe:mono
lang: en-EN

exclude-directories:        # directories Decker ignores
  - code
  - bin

poll-server: wss://example.com/quizzer/quiz   # WebSocket for polls
save-polls: true

publish:
  rsync:
    destination: server:/path

bibliography: /bibliography/refs.bib   # BibTeX file
csl: /bibliography/style.csl           # citation style

static-resource-dirs:       # additional static files copied to public/
  - static
  - code/data

template:
  css:
    - /static/custom.css

reveal:                     # reveal.js options
  center: true
  controls: true
  menu: true
```

## Typical directory structure

```
project/
├── decker.yaml              # Decker configuration
├── CLAUDE.md                # AI assistant instructions
├── CONTENT-FORMATS.md       # syntax reference (this guide supersedes it)
├── static/                  # CSS, images, shared resources
├── bibliography/            # BibTeX and CSL files
├── unit/                    # main lecture decks (01-deck.md, ...)
├── topic/                   # topic content
│   └── functional/
│       ├── recursion.md
│       └── quests/
│           └── recursion-quest.yaml
├── assignments/             # assignment pages (a01-page.md, ...)
└── public/                  # BUILD OUTPUT (gitignored)
```
